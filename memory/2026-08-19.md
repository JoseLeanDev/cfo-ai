## Cron de Mission Control — Fix Completo

**Problema:** El cron anterior (`58bb3e6a-cdaf-4430-8a7f-0b326b54b1a7`) corría en sesión `isolated`. Cuando fallaba, el error quedaba atrapado en la sesión aislada y nunca llegaba al usuario. El usuario nunca se enteraba de que algo estaba roto.

**Solución:** Se creó un nuevo cron `e1645f3e-a3c5-4264-8cc5-5b5c54360b6b` con:
- `--session main` (no isolated) para que despierte directamente en la conversación
- `--system-event heartbeat-check` como trigger
- `--cron "0 * * * *"` (cada hora en punto)
- `--tz America/Guatemala`
- `--to 7148683500`

**Resultado:** A las 05:04 GMT+8 (21:04 GT) el cron ejecutó exitosamente y me despertó en la conversación. ✅

**Clave:** Siempre usar `--session main` para cron jobs que necesitan notificar al usuario. Isolated sessions silencian errores.

## Distinción: Heartbeats de Mission Control vs Heartbeats del Sistema Financiero

Los heartbeats que aparecen en el dashboard de Mission Control (tab "Heartbeat History") son del **sistema financiero de CFO AI** (agentes de liquidez, rentabilidad, caja chica, etc.). Son independientes del cron de tareas de Mission Control.

- **Heartbeats financieros:** Cada 30 min, ejecutan análisis financiero automático
- **Cron de tareas:** Cada hora, revisa `mc_tasks` por trabajo pendiente

El usuario confundió los dos. Los heartbeats antiguos NO indican que el cron estaba funcionando — solo que el sistema financiero estaba activo.

## Flujo de Trabajo con Mission Control

1. Heartbeat ejecuta cada hora
2. Revisa `mc_tasks` WHERE status IN ('todo', 'backlog')
3. Si hay tareas → Mover a `in_progress` + notificar al usuario
4. Trabajar inmediatamente sin esperar aprobación
5. Hacer commit + push
6. Actualizar tarea a `done`

**Regla:** Si tarea está en `review` con feedback → leer feedback y actuar. NO molestar al usuario si solo está esperando aprobación.

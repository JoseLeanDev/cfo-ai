## 🔄 WORKFLOW CORRECTO (del screenshot de Jose)

### Crear una nueva tarea:
1. **Mission Control Frontend** → Usuario abre "New Task"
2. **Selecciona Project** del dropdown (CFO AI / Abaco, Lavandería Demo, Mission Control)
3. **Guarda tarea** en `mc_tasks` con `project_id` → `mc_clients.id`

### Trabajar en una tarea asignada:
1. **Yo recibo la tarea** → Leo `mc_tasks` donde `assignee = 'Jose'` (o el asignado)
2. **Obtengo `project_id`** de la tarea
3. **Busco en `mc_clients`** con ese `project_id` → obtengo `slug` (ej: `abaco`)
4. **Busco en `abaco_master.clients`** con ese `slug` → obtengo contexto COMPLETO + `database_name`
5. **Conecto a `database_name`** (ej: `cfo_ai_db`) → trabajo con datos del negocio
6. **Reporto progreso** → Actualizo status de la tarea en `mc_tasks`

### Estructura de datos:

**`mission_control_e9jm.mc_tasks`** (tabla local de tareas):
| Campo | Tipo | Descripción |
|-------|------|-------------|
| `id` | integer | ID de la tarea |
| `title` | varchar | Título |
| `description` | text | Descripción |
| `project_id` | integer | **Referencia a `mc_clients.id`** |
| `status` | varchar | backlog / todo / in_progress / review / done |
| `priority` | varchar | low / medium / high / urgent |
| `assignee` | varchar | Quién la debe hacer |
| `tags` | jsonb | Tags |

**`mission_control_e9jm.mc_clients`** (clientes locales):
| Campo | Descripción |
|-------|-------------|
| `id` | ID local (usado en `mc_tasks.project_id`) |
| `name` | Nombre del cliente |
| `slug` | Slug único (ej: `abaco`, `lavanderia-demo`) |
| `status` | active / inactive |

**`abaco_master.clients`** (contexto maestro del agente):
| Campo | Descripción |
|-------|-------------|
| `id` | ID maestro |
| `slug` | **Mismo slug que `mc_clients.slug`** ← MATCH KEY |
| `name` | Nombre |
| `database_name` | **Base de datos de negocio** (ej: `cfo_ai_db`) |
| `business_context` | JSONB con todo el contexto de negocio |
| `financial_context` | JSONB con contexto financiero |
| `operational_context` | JSONB con tech stack, integraciones |
| `project_context` | JSONB con fase, features, milestones |
| `data_context` | JSONB con fuentes de datos |
| `ai_context` | JSONB con preferencias de IA |

### Flujo de match:
```
mc_tasks.project_id → mc_clients.id → mc_clients.slug
→ abaco_master.clients.slug → abaco_master.clients.database_name
→ [Conectar a base del cliente]
```

## 🔐 REGLA ABSOLUTA: Base de Datos por Cliente

**Cada cliente tiene su propia base de datos.** `abaco_master` solo me dice cuál es.

| Cliente (abaco_master) | database_name | Base de datos de negocio |
|------------------------|--------------|-------------------------|
| CFO AI / Abaco | `cfo_ai_db` | PostgreSQL Render (datos del negocio) |
| Lavanderia Demo | `abaco_lavanderia_db` | PostgreSQL Render (datos del negocio) |
| Mission Control | `mission_control_e9jm` | PostgreSQL Render (datos del negocio) |

**Proceso de trabajo:**
```
1. Recibir tarea → obtener project_id de mc_tasks
2. Buscar mc_clients (project_id) → obtener slug
3. Buscar abaco_master.clients (slug) → obtener contexto + database_name
4. Conectar a database_name del cliente
5. Ejecutar tarea con contexto completo
```

**¿Qué está en cada base?**

| Base de Datos | Qué contiene | Para qué la uso |
|--------------|-------------|----------------|
| `abaco_master` | Contexto de TODOS los clientes | Saber a quién pertenezco, qué proyecto, qué tech stack, qué fase, qué base usar |
| `mission_control_e9jm` | Tareas (`mc_tasks`) + Clientes locales (`mc_clients`) | Gestión de tareas y proyectos en Mission Control |
| `cfo_ai_db` | **SOLO datos del negocio de CFO AI** | Transacciones, CxC, CxP, insights de ESE cliente |
| `abaco_lavanderia_db` | **SOLO datos del negocio de Lavandería** | Transacciones, CxC, etc. de ESE cliente |

**NUNCA confundir:** `abaco_master` es el cerebro. La base del cliente es el cuerpo (datos).
